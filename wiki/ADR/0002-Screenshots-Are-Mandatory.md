# ADR-0002: Screenshots are mandatory

|              |               |
| ------------ | ------------- |
| **Status**   | Accepted      |
| **Date**     | 2026-10-01    |
| **Deciders** | Falco Schmutz |

## Context

A repository's README says what it does; it rarely shows it. A reader deciding
whether a repository is the one they want — a teammate, a customer, the person
on call — learns more from one image than from the purpose line, and most of
our repositories have something to show: a dashboard, a site, a CLI's output, a
generated report, or, at the very least, the configured repository itself.

Left as a convention, screenshots do not happen, and when they do they rot: the
image shows last year's interface, links to a file that was renamed, or weighs
four megabytes. A rule that is only written down is a rule nobody enforces.

Two constraints shape the answer. The template already has exactly one
documentation surface — `wiki/` — and CI failed on any `docs/` directory.
And some repositories genuinely have nothing visual: a pure library, a data-only
repository.

## Decision

Every repository made from this template has screenshots, and CI enforces it.

- Images live in `docs/screenshots/` (`.png`, `.jpg`, `.webp`, at most 600 KB
  each) and README.md has a `## Screenshots` section linking at least one of
  them with non-empty alt text. Every image is referenced from README.md or a
  wiki page; every referenced path exists.
- `scripts/check-screenshots.sh` (bash and coreutils only, generic, copied
  byte-identical into other repositories) is the single implementation. It runs
  in the `screenshots` job of `ci.yml`, which the ruleset example requires, and
  as a pre-commit hook. It is part of Bundle A — core.
- The only way out is declared: `.github/screenshots-exempt`, whose first
  non-comment line states the reason. The check prints the reason and passes.
  An empty or comment-only file fails.
- `docs/` may now exist, but only as `docs/screenshots/`. Images are assets,
  not a second documentation surface; prose still lives in `wiki/`, and the
  `template structure` job fails on anything else under `docs/`.
- The template itself complies with real screenshots of what it produces,
  regenerated by `scripts/screenshots/capture.sh`. Screenshots never contain
  customer data, real names, or credentials.

## Consequences

- **Good** — every repository shows what it is on its front page, and the image
  cannot silently point at a deleted file or balloon past 600 KB.
- **Good** — the exemption is reviewable: it is one file with one reason, and it
  shows up in a diff.
- **Bad** — every visible change now carries a chore: regenerate the screenshot
  in the same pull request. The check catches a missing file, not a stale one;
  staleness is still on the reviewer, via the pull request checklist.
- **Bad** — binary files in the history. 600 KB per image keeps it bounded, and
  `check-added-large-files` stays at 1 MB as a backstop.
- **Bad** — the template's own capture needs `gh`, Python with PyYAML, and a
  borrowed Playwright install; it is a maintainer tool, not something CI runs.
- **Neutral** — `docs/` exists in the tree, narrowed to images. The
  one-documentation-surface rule is unchanged in substance.

## Alternatives considered

- **Recommend screenshots in CONTRIBUTING and stop there.** Rejected: that is
  the state that produced repositories with none.
- **Keep images in `wiki/`.** Rejected: the README cannot reliably embed an
  image from the wiki repository, the README is the page people land on, and a
  wiki image is outside the pull request that changed the interface.
- **Commit images anywhere and only check the README link.** Rejected: without
  a fixed directory there is no orphan check, and unreferenced images pile up.
- **A per-repository opt-in bundle.** Rejected by the owner: an optional rule is
  not a rule. The exemption file covers the repositories with nothing to show.
- **Git LFS for images.** Rejected for now: per-repository setup and bandwidth
  cost for files that a 600 KB cap already keeps small.
